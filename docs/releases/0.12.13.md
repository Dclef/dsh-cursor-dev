# dsh-cursor-dev 0.12.13

> 发布日期：2026-11-20（Asia/Shanghai）。开发基线仍为 DSH 0.2.1-rc.5；兼容范围和依赖版本不变。

## 修复

- 运行失败原因不再丢失：`tool.js` 调用 `mirrors.close()` 时只传 `stopReason`，镜像子会话因此只能渲染兜底文案 `run failed: error`，而真实原因只存在于工具结果里。现在失败消息随 `error` 字段一并写入子会话，`turnEndReason()` 直接使用它，不再显示 `cursor/run-failed` 的空壳描述。

## 新增

- Cursor CLI 版本探测：`lib/cli.js` 新增 `agentVersion` / `parseAgentVersion` / `forgetAgentVersion`，执行 `agent --version` 并缓存 10 分钟；`agentVersion` 永不抛错（答案只用于展示），`?auth=refresh` 强制重探。状态接口新增 `version: { ok, version, error }`。
- 安装版本比对：`lib/resolve-agent.js` 新增 `buildStampOf` 与 `newestInstalledBuild`。`resolveAgent` 只在插件加载时解析一次，官方安装器把新版放进 `versions/<stamp>` 目录后，进程仍驱动旧版直到 DSH 重启。状态接口新增 `build: { running, installed, stale, note }`。
- 面板显示构建号：头部常驻 `CLI <stamp>`（悬停显示完整路径与错误），setup 卡片同样带版本；`stale` 时提示「已装新版但当前仍跑旧版，重启 DSH 生效」。中英文文案齐备。

## 验证

- Windows、DSH 0.2.1-rc.5 开发基线：323 项，313 通过、0 失败、0 取消、10 跳过。
- 10 项跳过为 Windows 平台上不适用的认证存储测试；不代表 macOS 已验收。
- 新增 10 项回归：`test/agent-version.test.mjs`（构建号解析、包装器输出、静默不算版本、缓存与强制重探、CLI 拒绝回答、无 CLI 不 spawn）与 `test/build-stamp.test.mjs`（版本目录提取、裸二进制不猜、按日期取最新、无 versions 目录）。
- 真实探测实测：`agent --version` → `2026.11.19-f005e9d`，`build.stale=false`。
- `git diff --check` 无格式问题。常规测试不启动真实 Cursor 或查询真实账户；仅显式设置 `DSH_CURSOR_LIVE_TESTS=1` 才启用真实冒烟。
- 离线测试通过不等同于运行中 GUI 已自动加载新代码；需更新实际安装副本并重启 DSH。

## 安装与生效

- npm 来源：在 DSH 当前 profile 的插件管理中更新 `dsh-cursor-dev`；固定版本可使用 `dsh-cursor-dev@0.12.13`。
- Git/市场来源：更新 `Dclef/dsh-cursor-dev` 仓库来源。
- 固定快照：安装发布附件 `dsh-cursor-dev-0.12.13.tgz`。
- **等待运行任务完成，更新实际安装的插件，然后重启 DSH 并刷新页面。** 新代码作用于之后的新任务；历史日志中未保存的内容不会自动补齐。
