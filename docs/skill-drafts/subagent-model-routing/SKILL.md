# 子智能体模型路由与参数校验

## 适用范围

调用 `subagent`、选择子智能体的提供方、模型或推理等级，或排查以下错误时使用：

- `Error: child LLM \`provider\` must be non-empty`
- 子智能体模型路由不被当前 Session 允许
- provider 与 model 不成对，或推理等级无效

本技能只约束子智能体模型参数。用户明确指定专家、专家团或其他工具时，遵守对应工具的要求。

## 调用规则

1. **使用默认模型时，省略 provider、model、reasoning_effort 三个键。** 不用空字符串、空白字符串、null 或猜测值表示默认。
2. **显式指定模型前，先调用 list_subagent_models。** 先查提供方，再按需查模型及其推理等级。使用返回的 ID，不从父会话模型、自身模型身份或显示名称推断。
3. **provider 和 model 必须成对且非空。** 只有一个字段时，先补齐可验证的信息；本意为默认时，删除全部路由字段。
4. **reasoning_effort 只使用目标模型公布的有效值。** 不要求固定等级时省略；不要硬套父模型等级。
5. **目录与当前 Session 的允许路由分别校验。** 目录存在不保证当前会话允许。如果路由被拒绝，不猜另一个提供方、不反复碰撞。默认模型满足用户要求时，删除全部路由字段重试一次；用户锁定模型时，说明具体限制，不擅自替换。
6. **不同工具的模型接口不能混用。** subagent 的路由、cursor_code 的 Cursor 模型、cursor_subagent 的默认配置和专家工具的专家名称不是同一接口。subagent_fork 不接受这些模型覆盖字段。
7. **只发送实际需要的受支持字段。** 不为填满对象而给可选字段补空字符串。若调用层强制要求这些字段，检查正确调用方式；仍无法表达省略时报告接口限制，不伪造 ID。

## 发送前检查

- 默认调用：三个可选键都不存在。
- 指定调用：provider/model 是已查证、成对的非空 ID。
- reasoning_effort 若存在，与目标模型匹配。
- prompt 是完整、可独立执行的任务说明；cwd 是实际工作区。
- 没有把父会话或其他工具的模型名称当作已验证路由。

## 默认调用示例

```json
{
  "cwd": "E:/example/project",
  "description": "核对额度显示逻辑",
  "prompt": "只读检查当前工作区的额度规范化和显示逻辑，给出字段语义与最小修复建议，不修改文件。"
}
```

指定模型时，查询目录后把返回的 provider/model 成对加入。仅在需要固定、且已确认有效时加入 reasoning_effort。本技能不保存固定提供方、模型或等级示例值，以免以后照抄失效。

禁止发送：

```json
{
  "provider": "",
  "model": "",
  "reasoning_effort": ""
}
```

## 失败后的处理

- provider must be non-empty：检查是否把可选字段传成空字符串；默认分支删除三个键，再调用一次。
- provider/model 不成对：查询目录并补齐，或切回省略全部路由字段的默认分支。
- 路由不允许：按会话权限限制处理，不通过改拼写绕过。
- 推理等级无效：查询目标模型详情；不需要固定时省略。
- 参数校验失败时，子智能体没有启动。只有成功结果包含子智能体 ID，才记为已启动；交付前必须收集实际结果。

修正参数后继续用户已授权的原任务；不要将工具参数错误归因于用户项目或账户额度。
