# Cursor 执行可见性与异常收尾验收

> 日期：2026-11-03（Asia/Shanghai）；基线：main / 7bbb471 / 0.12.9。记录范围：发布前源码修复与离线验收阶段；当前发行版说明见 README 与 GitHub Release。当前 DSH 未重启实测。

## 一、问题与根因

- CLI 的 tool_call 归一化只写 title/kind/path，缺少镜像消费者真正读取的 name/input，导致工具名统一退成 cursor tool、请求显示为 {}。
- CLI 的读文件/命令结果没有带入镜像，只剩 completed 和路径；完成事件省略 args 时又覆盖了开始时的路径。
- CLI 错误只携带正文和 diff，丢失 calls/耗时；运行失败后工具出口固定返回 changes=[]，即便实际文件已修改也渲染 files changed: NONE。
- 退出 Promise 的异常被吞掉，没有核对进程退出码/信号；CLI 的 success JSON 不能单独证明进程成功退出。
- 扫描上限或不可读路径可能形成不完整快照，旧比较逻辑会据此误报新增/删除；只有 completed 的工具也会从时间线丢失。

## 二、源头修复

| 模块 | 行为 |
|---|---|
| [CLI 解析器](../../../lib/cli-runner.js) | 给工具传递真实 name/input/output，完成事件保留已有参数与路径；输出有字符上限；保留错误正文与终态 result 文本。 |
| [子会话镜像](../../../lib/mirror.js) | 工具卡展示真实参数、读文件结果和命令错误；取消工具不标记为成功。 |
| [执行与结果](../../../lib/tool.js) | 失败/取消时仍在本轮执行租约内比较前后指纹，保留实际 changes/preview/步骤/部分正文与详细推理；失败会话可持久续接。 |
| [文件证据](../../../lib/changes.js) | 不可读/截断标记为不完整；前快照不完整不能推断新增，后快照不完整不能推断删除，仍保留双方都观察到的修改。 |
| [时间线](../../../lib/journal.js) | 即便缺少 started 也保留 observed completed/failed 工具；不凭空声称未完成步骤成功。 |

失败摘要保留退出码、终止信号、stderr 尾部和持久化警告。只有完整扫描才可断言没有检测到文件变更；无法取得证据显示 UNKNOWN，部分扫描显示 PARTIAL，不拿空数组冒充“未改文件”。这些都是观测结果，不是声称所有修改必由 Cursor 独占产生的审计证明。

CLI 缺少 result 仍然失败，不改成“正文非空即成功”，不自动重跑有副作用的任务。不承诺修复上游 CLI 本身的异常退出，而是避免将部分执行丢掉或误报成功。

## 三、先红后绿与最终验证

- 首批 CLI 细节/缺终态/实际非零退出/终态正文/工具错误的 5 项新测试先全部失败，修复后通过。
- 失败/取消后的落盘文件、失败会话续接、扫描前失败不可声称 NONE 的 3 项先失败，修复后通过。
- 不完整扫描与 completed-only 时间线的 6 项中，原有正确修改识别项通过，其余 5 项先失败，修复后全部通过。
- 增加真实 CLI 解析器 → 真实 CursorMirror 的离线集成，以及 done 提前 reject、信号退出、父级取消/监听器清理和取消卡片断言。未用预先归一化事件代替关键接通用例。

最终命令（从仓库根目录运行；PowerShell）：

```powershell
$env:DSH_CURSOR_LIVE_TESTS = '0'
npm test
```

实际结果：**301 项，291 通过，0 失败，0 取消，10 跳过**，耗时 **7002.6522 ms**，退出码 **0**。跳过项为 3 项真实 Cursor/账户调用和 7 项不适用 Windows 的认证存储测试。没有删弱原有业务断言。

首次全量尝试使用名称排除表达式，但没有可靠隔离仓库原有的 3 项真实冒烟，错误模型场景因 ACP 连接关闭而失败；那次是 291 项、283 通过、1 失败、7 跳过，**不算离线通过**。随后将这 3 项改为明确的 `DSH_CURSOR_LIVE_TESTS=1` 才启用，最终验证明确设置为 0；正常 npm test 默认不会启动真实 Cursor 或查询账户额度。启用真实冒烟可能消耗账户额度，不能当普通单元测试运行。
